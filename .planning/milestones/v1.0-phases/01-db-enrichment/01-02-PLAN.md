<!-- Correct Church API response structures. -->

LEVEL 1 — Conference endpoint:
```
GET https://www.churchofjesuschrist.org/study/api/v3/language-pages/type/dynamic?lang=eng&uri=/general-conference/{year}/{month}
```
Response structure:
```json
{
  "toc": {
    "entries": [
      {},
      {
        "section": {
          "entries": [
            {
              "content": {
                "uri": "/general-conference/2025/10/19oaks",
                "title": "Introduction",
                "subtitle": "Dallin H. Oaks"
              }
            }
          ]
        }
      }
    ]
  }
}
```
- `toc.entries[0]` is NOT a session — skip it
- `toc.entries[1:]` are sessions
- Each session's talks: `session["section"]["entries"]`
- Each talk has ONLY: `content.uri`, `content.title`, `content.subtitle` (speaker name)
- NO `preview` field. NO `id`/`data_aid` field at this level.

LEVEL 2 — Individual talk endpoint:
```
GET https://www.churchofjesuschrist.org/study/api/v3/language-pages/type/dynamic?lang=eng&uri={talk_uri}
```
- Preview: `api_response["content"]["content"]["head"]["page-meta-social"]["pageMeta"]["description"]`
- `data_aid` is also available per-talk

NOTE: `api/extract_conference_sections.py` is useful ONLY for:
- `requests_cache.install_cache(...)` setup pattern
- `get_conferences()` DB query pattern
It does NOT correctly reflect the conference API response structure.

Create `api/fetch_talk_previews.py` using the two-level Church API fetch pattern. The script must:

1. **Configuration (top of file):**
```python
API_BASE_URL = "https://www.churchofjesuschrist.org/study/api/v3/language-pages/type/dynamic?lang=eng&uri="
REQUEST_TIMEOUT = 30
OUTPUT_PATH = os.path.join(os.path.dirname(os.path.dirname(__file__)), "db", "one-off-migration", "talk_previews.json")
```

2. **Install requests_cache** (copy from extract_conference_sections.py):
```python
requests_cache.install_cache("http_cache", backend="sqlite", expire_after=requests_cache.NEVER_EXPIRE)
```

3. **`get_conferences(db_path)`** — Query `SELECT ID, Year, Annual FROM conference ORDER BY Year, ID` from core.52.db. Return list of (id, year, annual) tuples.

4. **`get_uri_gc_lookup(db_path)`** — Build a mapping from `uri_gc` path to `talk.ID`:
```python
# Query: SELECT ID, URI_GC FROM talk WHERE URI_GC IS NOT NULL AND Corpus IN ('E', 'G')
# Return dict: {uri_gc_path: talk_id}
# uri_gc may be a full URL or path — normalize to path portion only
```

5. **`fetch_conference_talk_uris(year, annual)`** — Fetch talk URI list from the conference endpoint:
   - Map annual: `month = "04" if annual == "A" else "10"`
   - URL: `f"{API_BASE_URL}/general-conference/{year}/{month}"`
   - Parse: iterate `data["toc"]["entries"][1:]` (skip index 0)
   - For each session entry: iterate `session["section"]["entries"]`
   - Each talk entry: extract `entry["content"]["uri"]`, `entry["content"]["title"]`, `entry["content"]["subtitle"]`
   - Return list of dicts: `{"uri": ..., "title": ..., "subtitle": ...}`
   - Handle HTTP errors, missing keys, empty responses gracefully with logging (do not crash)

6. **`fetch_talk_preview(talk_uri)`** — Fetch preview for a single talk:
   - URL: `f"{API_BASE_URL}{talk_uri}"`
   - Navigate: `data["content"]["content"]["head"]["page-meta-social"]["pageMeta"]["description"]`
   - Return the description string, or None if not found
   - Handle errors gracefully with logging

7. **`main()`** with argparse:
   - `--db` (default: CORE_DB_PATH from db/__init__.py import or hardcoded fallback)
   - `--output` (default: OUTPUT_PATH above)
   - `--dry-run` (log what would happen, don't write file and don't make Level 2 calls)
   - In dry-run: iterate conferences, fetch Level 1 URIs, print counts, then stop
   - In full run: for each talk URI collected, call `fetch_talk_preview()`, match to talk_id via uri_gc lookup, collect results
   - Save to JSON with `encoding='utf-8'` and `ensure_ascii=False`
   - Print coverage summary: total URIs collected, total previews found, total matched to talk_ids, total unmatched

Output JSON format: `[{"talkID": int, "title": str, "uri": str, "preview": str}, ...]`

Use sequential fetching (no threading) to be polite to the API. requests_cache ensures re-runs are fast.
