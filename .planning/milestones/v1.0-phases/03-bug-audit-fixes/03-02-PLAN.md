    **Step 1 — Run the audit:**
    Execute `pipenv run py scripts/run_audit.py` and capture all output. The script runs each talk_id through Phases 1-5 and reports errors.

    **Step 2 — Analyse failures:**
    For every error or unexpected output:
    - Identify the phase, the talk_id, and the exact error
    - Read the relevant extractor source code to diagnose root cause
    - Determine if it is a genuine bug (wrong behavior) vs expected edge case (e.g., talk has no citations)

    **Step 3 — Catalogue bugs:**
    Add a new row to `docs/pipeline/phase-3-citation/BUGS.md` for each genuine bug discovered. Use the next sequential BUG-NN ID. Set status to `open` initially.

    **Step 4 — Fix each bug:**
    For each catalogued bug:
    - Apply a root-cause fix (per D-01/BUGS-02: no workarounds)
    - Update the bug's status in BUGS.md from `open` to `fixed`
    - Verify the fix does not break existing tests: `pipenv run py -m pytest tests/ -v --tb=short`

    **Step 5 — Re-run audit:**
    After all fixes, re-run `pipenv run py scripts/run_audit.py` to confirm zero errors on the sample.

    Note: The `files_modified` list above covers all extractor files that MIGHT need fixes. Only modify files where actual bugs are found. If the audit finds zero new bugs, simply update BUGS.md to note "Audit completed — no additional bugs found" and move on.
