    Read each test carefully to understand the existing HTML structure before modifying. Only change the container class — do NOT alter the inner content or assertions.

    **Fix 3 — Phase 2 `is_container_element` for div.figure (1 test):**
    In `extractors/phase2_paragraph_extraction.py`, function `is_container_element()` (around line 590), add `div.figure` recognition. After the stanza check (line 593-594), add:
    ```python
        if "figure" in classes:
            return True
    ```
    This makes `is_container_element()` return `True` for `<div class="figure">`, matching its docstring. Note: `extract_semantic_paragraphs()` already handles `div.figure` explicitly at line 762 via `process_element()` before the `is_container_element` branch, so this fix corrects the unit function behavior without creating double-processing.

    **Fix 4 — Phase 2 bare `<li>` text handling (2 tests):**
    In `extractors/phase2_paragraph_extraction.py`, function `extract_list_item_paragraphs()` (starts at line 358), add a fallback after the existing `for element in li_element.descendants:` loop (after line 456). If `paragraphs` is still empty after the loop, extract the bare text content of the `<li>` element using `_element_clean_text(li_element)`. If the text meets `min_paragraph_length`, append a paragraph dict with the same structure (text, text_raw, list_header, list_item_index, position_in_item=1). This handles `<li>text content</li>` without a wrapping `<p>`.

    **Fix 5 — Remove debug print statements:**
    In `extractors/phase2_paragraph_extraction.py`, remove the two `print()` calls at lines 644-645 inside `extract_semantic_paragraphs()`:
    ```python

    print(element)              # DELETE
    ```

    These violate the project logging convention (`logger = logging.getLogger(__name__)`). If stanza detection logging is desired, replace with `logger.debug("Stanza detected: %s", element.name)` — but the research suggests simply removing them.
