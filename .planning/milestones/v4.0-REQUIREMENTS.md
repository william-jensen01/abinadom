**Archived:** 2026-07-02
**Status:** All requirements satisfied

## Milestone v4.0 Requirements

### Benchmark Framework

- [x] **BENCH-01**: User can transform talk data into ChromaDB-safe flat metadata and native rich metadata via shared `flatten_metadata` / `rich_metadata` / `prepare_*` functions — Phase 20
- [x] **BENCH-02**: User can load talk bundles into a benchmark ChromaDB instance via a benchmark-specific ChromaDB loader — Phase 21
- [x] **BENCH-03**: User can load talk bundles into Weaviate (with schema creation and UUID mapping) via a Weaviate loader — Phase 21
- [x] **BENCH-04**: User can load talk bundles into Qdrant (with collection creation and payload indexes) via a Qdrant loader — Phase 21
- [x] **BENCH-05**: User can measure upsert speed, query latency (p50/p95/p99), concurrency throughput, and memory delta via metric dataclasses and `recall_at_k` — Phase 20
- [x] **BENCH-06**: User can run a canonical query set (paragraph + citation queries with and without filters) as the standard workload for all three DBs — Phase 20
- [x] **BENCH-07**: User can run the full benchmark from CLI (`benchmark/runner.py`) and receive a structured JSON report — Phase 22

### Evaluation

- [x] **EVAL-01**: User can start ChromaDB, Weaviate, and Qdrant locally via a single Docker Compose file — Phase 20
- [x] **EVAL-02**: User can run a full benchmark (upsert, query latency, concurrency, memory) against all three DBs in a single command — Phase 23
- [x] **EVAL-03**: Each DB is fully populated with all 5,838 talks before query and concurrency benchmarks run, ensuring comparable results — Phase 23
- [x] **EVAL-04**: User can see recall@k10 and recall@k50 comparing Weaviate vs ChromaDB and Qdrant vs ChromaDB — Phase 23
- [x] **EVAL-05**: User can read a written decision report identifying the winning DB with rationale — Phase 23 (`benchmark/DECISION.md`)

### Migration

- [x] **MIGR-01**: User can run the full pipeline against the winning DB via an updated `scripts/run_pipeline.py` (Phase 6 loader swapped) — Phase 24
- [x] **MIGR-02**: MCP server uses the winning DB client at runtime (server.py startup validation updated) — Phase 24
- [x] **MIGR-03**: Production Docker Compose stack uses the winning DB service (docker-compose.yml updated, .env.example reflects new vars) — Phase 24
- [x] **MIGR-04**: Winning DB is populated with all 5,838 GC talks and MCP `search` + `get_talk` tools verified end-to-end — Phase 24 (human-gated verification, 2026-07-02)

## Future Requirements (carried to next milestone)

- Journal of Discourse and scriptures content — next milestone
- Multi-user / hosted deployment support
- Re-embedding with an updated model (if nomic-embed-text is superseded)

## Out of Scope

- Supporting multiple vector DBs in production simultaneously — one DB in production at a time; ChromaDB removed after migration
- Re-embedding — same Ollama nomic-embed-text model used throughout benchmark and migration
- Migrating SQLite — read-only source of truth stays unchanged
- Journal of Discourse or scriptures content — future milestones
