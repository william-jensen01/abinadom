# Milestone v2.0: MCP Server

**Status:** ✅ SHIPPED 2026-04-03
**Phases:** 9–12 (including 9.1 inserted)
**Total Plans:** 7

## Overview

Expose ChromaDB via a local MCP server so Claude Desktop can search by meaning, read full talks, and engage conversationally with General Conference content. Built on top of the v1.0 pipeline (5,838 talks / 202,175 paragraphs / 67,307 citations / 25,608 footnotes already in ChromaDB).

## Milestone Summary

**Decimal Phases:**

- Phase 9.1: Paragraph Metadata Enrichment (inserted after Phase 9 — gap identified during Phase 10 planning)

**Key Decisions:**

- FastMCP lifespan @asynccontextmanager chosen over inline __main__ startup — cleaner lifecycle integration
- get_collection() not get_or_create_collection() as ChromaDB startup guard — prevents silent empty-DB creation
- Speaker filtering is Python post-filter (not ChromaDB where) — ChromaDB 1.5.5 has a silent bug on metadata string filters
- Paragraph metadata denormalized at load time (not runtime lookup) — eliminates secondary ChromaDB call per search result
- OLLAMA_URL env var is a base URL; /api/embeddings suffix always appended in get_embedding_function
- Two-layer prompting: FastMCP mcp.instructions (tool-level) + Project system prompt (adaptive persona)
- Config template uses absolute virtualenv Python path as command field; no cwd field

**Issues Resolved:**

- Paragraph metadata missing from ChromaDB records — resolved by Phase 9.1 insertion
- Nyquist validation not run for any phase — resolved in Phase 12
- SUMMARY frontmatter incomplete on 10-02 and 11-01 — resolved in Phase 12
- OLLAMA_URL double-read in server.py — resolved in Phase 12 (single `_resolve_ollama_url()` call)

**Issues Deferred:**

- VER-06 live ChromaDB enrichment check requires user `--force` re-run (documented as D-04 expected user action)
- Remote/mobile access — Milestone 3

**Technical Debt Incurred:**

None — Phase 12 closed all audit-identified tech debt before archival.
