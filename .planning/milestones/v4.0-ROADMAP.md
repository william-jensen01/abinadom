## Milestone Summary

**Inserted Phases:**
- Phase 22.1: Address Recall@k = 0.0 Bug (inserted after Phase 22 — urgent correctness fix)
- Phase 22.2: Optimize Benchmark Loaders for Efficiency (inserted after Phase 22.1 — upsert time 2-7h → feasible)

**Key Decisions:**
- Weaviate selected over ChromaDB and Qdrant: serial p50 42ms, filtered p50 51ms (4× faster than ChromaDB/Qdrant), cold-start 34ms, memory delta 0.02 MB, recall@k10=0.9875 — decisive on all dimensions
- doc_id_str as TEXT property in Weaviate schemas (Phase 22.1) — Weaviate query() was falling back to UUID strings; storing doc_id_str alongside UUID gives stable set-intersection key for recall computation
- ChromaDB collection name resolution in query() (Phase 22.1) — short keys like "paragraphs" must be resolved through CHROMADB_COLLECTION_NAMES before calling get_or_create_collection, otherwise a phantom empty collection is silently created
- AppContext holds only weaviate.WeaviateClient — collections.use() called inline per tool call (D-02)
- WeaviateLoader.load() collection_map uses self.COLLECTIONS[i] — ProductionWeaviateLoader routes to production names without re-implementing load()
- weaviate.connect_to_embedded() unsupported on Windows (gh#3315) — tests use platform-conditional fixture with MagicMock fallback
- OllamaEmbedder uses one requests.post per text (Ollama /api/embeddings is single-text-per-call)
- paragraphs_to_chromadb_format function name in phase2 preserved — only callee call site updated to to_db_record()
- CHROMADB_COLLECTION_NAMES re-added to pipeline_config.py for backward compat with verify_chromadb_pipeline.py (Phase 24)

**Issues Resolved:**
- recall@k = 0.0 for Weaviate and Qdrant — root causes: phantom ChromaDB collection + missing doc_id_str property in Weaviate schema (Phase 22.1)
- Upsert time estimated 2-7 hours — reduced to feasible range via batched embed calls + ThreadPoolExecutor parallelization (Phase 22.2)
- 34 failing server.py tests after Weaviate migration — resolved with full test_server.py rewrite (44 tests passing, Phase 24-08)
- Qdrant cold-start anomaly (369ms in smoke test) resolved to 115ms in full run

**Issues Deferred:**
- 2 pre-existing test failures in test_loaders_chromadb.py and test_metrics.py (unrelated to migration, carried forward)
- Scriptures content (OT, NT, BOM, D&C, POGP) — deferred to next milestone

**Technical Debt:**
- None material — ChromaDB fully removed from production paths; backward-compat CHROMADB_COLLECTION_NAMES retained in pipeline_config.py for verify_chromadb_pipeline.py (acceptable)
