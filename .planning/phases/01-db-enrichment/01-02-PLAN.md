3. **`get_conferences(db_path)`** -- Query `SELECT ID, Year, Annual FROM conference ORDER BY Year, ID` from core.52.db. Return list of (id, year, annual) tuples.

4. **`get_talk_id_lookup(db_path)`** -- Build a mapping from `data_aid` and `uri_gc` to `talk.ID` for matching API entries to database talks:
```python
# Query: SELECT ID, data_aid, URI_GC FROM talk WHERE Corpus IN ('E', 'G')
# Build two dicts: data_aid_to_id and uri_gc_to_id
# For uri_gc matching, extract the path portion (e.g., "/general-conference/2025/10/12stevenson")
```

5. **`fetch_conference_previews(year, annual)`** -- Fetch one conference from the API:
   - Map annual code: `month = "04" if annual == "A" else "10"`
   - URL: `f"{API_BASE_URL}/general-conference/{year}/{month}"`
   - Parse response JSON: iterate `data["toc"]["entries"]`, then each `section["entries"]`
   - For each entry, extract `uri`, `title`, `preview`, `id` (= data_aid)
   - Skip entries where `preview` is None or empty
   - Return list of dicts: `{"data_aid": entry["id"], "uri": entry["uri"], "title": entry["title"], "preview": entry["preview"]}`
   - Handle HTTP errors, missing keys, and empty responses gracefully with logging (do not crash)

6. **`match_to_talk_ids(entries, data_aid_lookup, uri_gc_lookup)`** -- Match API entries to talk IDs:
   - First try matching by `data_aid` (exact match)
   - If no match, try matching by `uri` against `uri_gc` values
   - Return list of dicts: `{"talkID": talk_id, "title": title, "uri": uri, "preview": preview}`
   - Log unmatched entries for debugging

7. **`main()`** with argparse:
   - `--db` (default: CORE_DB_PATH)
   - `--output` (default: OUTPUT_PATH above)
   - `--dry-run` (log what would happen, don't write file)
   - Iterate all conferences, fetch previews, match to talk_ids
   - Save to JSON file with `encoding='utf-8'` and `ensure_ascii=False`
   - Print coverage summary: total conferences fetched, total previews found, total matched to talk_ids, total unmatched

Keep the output JSON format compatible with the existing 34-entry format: `[{"talkID": int, "title": str, "uri": str, "preview": str}, ...]`

Use sequential fetching (not threaded) to be polite to the API. The `requests_cache` ensures re-runs are fast.
