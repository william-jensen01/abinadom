**Header:**

```
# Self-Deploy Guide
```

One-line intro: "Deploy the LDS MCP server on a Linux machine with Docker Compose."

**Section: `## Prerequisites`**
Bulleted list:
- Linux server (Ubuntu 22.04+ recommended)
- Docker Engine and Docker Compose v2 (`docker compose version` prints v2.x+)
- Ollama installed and running on the host with the `nomic-embed-text` model pulled (`ollama pull nomic-embed-text`)
- A populated ChromaDB directory (from running the pipeline, or copied from another machine)
- Git

**Section: `## Step 1: Clone the Repository`**
```bash
git clone https://github.com/YOUR_USERNAME/lds-mcp.git
cd lds-mcp
```

**Section: `## Step 2: Configure Environment Variables`**
```bash
cp .env.example .env
nano .env
```

Then show the full list of variables with explanations (sourced from .env.example):

| Variable | Description | Example |
|----------|-------------|---------|
| `OLLAMA_URL` | Ollama base URL (use `host.docker.internal` for host-side Ollama) | `http://host.docker.internal:11434` |
| `MCP_HOST` | Bind address inside container | `0.0.0.0` |
| `MCP_PORT` | Server port inside container | `7363` |
| `CHROMADB_DATA_PATH` | Host path to ChromaDB data directory | `/home/user/data/chromadb` |
| `AUTH_DATA_PATH` | Host path to auth.db file | `/home/user/data/auth.db` |
| `AUTH0_DOMAIN` | Auth0 tenant domain (for OAuth) | `your-tenant.auth0.com` |
| `AUTH0_AUDIENCE` | Auth0 API audience | `https://mcp.yourdomain.com` |
| `MCP_BASE_URL` | Public URL of the MCP server | `https://mcp.yourdomain.com` |

Important note: `CHROMADB_DATA_PATH` and `AUTH_DATA_PATH` are host-side directories. They must exist before starting:
```bash
mkdir -p /home/user/data/chromadb /home/user/data
```

**Section: `## Step 3: Start the MCP Server`**
```bash
docker compose up -d
```

Verify:
```bash
docker compose ps        # mcp-server should show "Up" / "healthy"
docker compose logs -f    # watch for "Uvicorn running on http://0.0.0.0:7363"
```

Test locally:
```bash
curl -f http://localhost:7363/health
```

Expected: JSON with `"status": "healthy"`.

**Section: `## Step 4: Set Up Public Access (Caddy + Cloudflare Tunnel)`**
One paragraph: "The infra/ directory contains a separate Compose stack that provides TLS termination (Caddy) and a public URL (Cloudflare Tunnel). Follow the full setup walkthrough:"

Link: **[infra/SETUP.md](../infra/SETUP.md)** (per D-05 — link, do not duplicate)

After completing infra/SETUP.md, verify end-to-end:
```bash
curl -f https://mcp.yourdomain.com/health
```

**Section: `## Step 5: Configure Auth0 (Optional)`**
Brief steps for Auth0 setup (needed for Claude.ai/Claude Desktop OAuth):
1. Create an Auth0 tenant at https://manage.auth0.com
2. Create an API with identifier matching your `AUTH0_AUDIENCE` value
3. Set `AUTH0_DOMAIN`, `AUTH0_AUDIENCE`, and `MCP_BASE_URL` in `.env`
4. Restart the MCP stack: `docker compose down && docker compose up -d`

Note: "Without Auth0 configured, the OAuth discovery endpoints return 404 and only static bearer tokens (via manage_keys.py) are available."

**Section: `## Updating`**
```bash
cd /path/to/lds-mcp
git pull
docker compose build
docker compose up -d
```

**Section: `## Troubleshooting`**
4-5 items:
- "Container exits immediately" — check `docker compose logs mcp-server`; common causes: ChromaDB path does not exist, Ollama unreachable
- "health returns unhealthy" — Ollama model not loaded (`ollama pull nomic-embed-text`) or ChromaDB collections empty
- "`network proxy declared as external, but could not be found`" — start the infra stack first (`cd infra && docker compose up -d`)
- "Permission denied on /data/auth.db" — ensure AUTH_DATA_PATH directory exists and is writable
- "Cannot connect to Ollama" — on Linux, `host.docker.internal` requires `extra_hosts` (already configured in docker-compose.yml); verify Ollama is listening on 0.0.0.0, not just 127.0.0.1
