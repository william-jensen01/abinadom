**Header:**

```
# Connecting to the LDS MCP Server
```

One-line intro: "This guide covers connecting MCP clients to a running LDS MCP server instance."

**Section: `## Prerequisites`**
- The server must be running and reachable (link to docs/DEPLOY.md for setup)
- You need the server's public URL (e.g. `https://mcp.yourdomain.com`)
- Verify connectivity: `curl -f https://mcp.yourdomain.com/health`

**Section: `## Claude.ai (OAuth 2.0)` (per D-08)**
Steps:
1. Open Claude.ai settings (or claude.ai/settings/integrations)
2. Click "Add MCP Server" (or "Add Integration")
3. Enter the server URL: `https://mcp.yourdomain.com/mcp`
4. Claude.ai will discover the OAuth metadata via `/.well-known/oauth-protected-resource/mcp` and redirect to Auth0 for login
5. Complete the Auth0 login/consent flow
6. After redirect, the MCP tools (search, get_talk) appear in Claude.ai

Note: The server implements RFC 9728 (Protected Resource Metadata) and proxies RFC 8414 (Authorization Server Metadata) from Auth0. Claude.ai handles the full OAuth 2.1 flow automatically.

**Section: `## Claude Desktop (Remote MCP)` (per D-08)**
Steps:
1. Open Claude Desktop settings > Developer > Edit Config
2. Add the server to `mcpServers` in the config JSON:
```json
{
  "mcpServers": {
    "lds-scripture-index": {
      "url": "https://mcp.yourdomain.com/mcp"
    }
  }
}
```
3. Restart Claude Desktop
4. Claude Desktop will perform the OAuth handshake with Auth0 automatically
5. After authentication, search and get_talk tools are available in chat

**Section: `## Other Clients (curl, HTTP)` (per D-08)**
Explain: For clients that do not support OAuth discovery, obtain an access token from Auth0 first, then include it in requests.

Sub-section: `### Obtaining a Token`
Show how to get a token via Auth0's /oauth/token endpoint:
```bash
curl -X POST https://YOUR_AUTH0_DOMAIN/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "client_credentials",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET",
    "audience": "https://mcp.yourdomain.com"
  }'
```
Note: Requires an Auth0 Machine-to-Machine application configured for the MCP API.

Sub-section: `### MCP Protocol Requests`
Show the MCP JSON-RPC protocol flow:

1. Initialize (no auth required):
```bash
curl -X POST https://mcp.yourdomain.com/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```
Note: Save the `Mcp-Session-Id` header from the response.

2. List tools (auth required):
```bash
curl -X POST https://mcp.yourdomain.com/mcp \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Mcp-Session-Id: SESSION_ID_FROM_STEP_1" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
```

3. Call a tool (auth required):
```bash
curl -X POST https://mcp.yourdomain.com/mcp \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Mcp-Session-Id: SESSION_ID_FROM_STEP_1" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"search","arguments":{"query":"faith and repentance","collection":"paragraphs","n_results":3}}}'
```

**Section: `## Discovery Endpoints`**
List the well-known endpoints the server exposes:

| Endpoint | Purpose |
|----------|---------|
| `GET /health` | Server health check (no auth) |
| `GET /.well-known/oauth-protected-resource` | RFC 9728 Protected Resource Metadata |
| `GET /.well-known/oauth-protected-resource/mcp` | RFC 9728 (MCP-specific path) |
| `GET /.well-known/oauth-authorization-server` | RFC 8414 Authorization Server Metadata (proxied from Auth0) |

**Section: `## Troubleshooting`**
3-4 items:
- "401 Unauthorized" — token expired or invalid; re-authenticate
- "404 on well-known endpoints" — AUTH0_DOMAIN or MCP_BASE_URL not configured in server .env
- "Connection refused" — server not running; check `docker compose ps` and `/health`
- "OAuth redirect fails" — verify Auth0 callback URLs include the client's redirect URI
