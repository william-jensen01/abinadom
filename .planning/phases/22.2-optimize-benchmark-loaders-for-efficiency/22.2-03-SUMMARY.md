## What Was Built

### Task 1: embed_fn Type Annotation Propagation

Updated four files to use the batch embed_fn signature introduced in plan 22.2-01:

- `loaders/__init__.py`: Updated docstring and `__init__` parameter from `Callable[[str], list[float]]` to `Callable[[list[str]], list[list[float]]]`
- `loaders/chromadb_loader.py`: Same `__init__` annotation update; `query()` now calls `self.embed_fn([query_text])[0]`
- `loaders/qdrant_loader.py`: Same `__init__` annotation update; `query()` now calls `self.embed_fn([query_text])[0]`
- `loaders/weaviate_loader.py`: Same `__init__` annotation update; `query()` now calls `self.embed_fn([query_text])[0]`

The `[query_text][0]` adapter wraps the scalar query string in a list (as required by the new batch signature) and unwraps the first result vector.

### Task 2: WeaviateLoader.load() insert_many

Replaced the stateful `col.batch.fixed_size()` context manager with a direct `col.data.insert_many()` call:

- Added `from weaviate.classes.data import DataObject` import
- Builds a `list[DataObject]` per collection using a list comprehension
- Calls `col.data.insert_many(objects)` once per collection
- Checks `result.has_errors` and logs each error UUID as WARNING (D-03)
- Wraps the entire `insert_many` call in `try/except` and logs exceptions as WARNING, continuing to the next collection (D-04)
- Removed: `col.batch.fixed_size`, `batch_ctx.add_object`, `col.batch.failed_objects`

This is safe for concurrent threads — no shared batch state between calls.

### Task 3: Test Stub Updates

Updated `_mock_embed` in all three integration test files from the old single-string form:
```python
def _mock_embed(text: str) -> list[float]:
    return [0.1] * 768
```
to the new batch form:
```python
def _mock_embed(texts: list[str]) -> list[list[float]]:
    return [[0.1] * 768 for _ in texts]
```
