## Fixed Issues

### CR-01: wrap bare string in embed_fn calls as single-item list

**Files modified:** `loaders/shared_transforms.py`
**Commit:** `183bb5a`
**Applied fix:** Changed all 8 occurrences of `embed_fn(document)` in the individual `prepare_*`
helper functions to `embed_fn([document])[0]`. This satisfies the `Callable[[list[str]], list[list[float]]]`
type contract: the bare string is wrapped in a list (producing a single-element batch call) and
`[0]` extracts the single vector from the result. The bundle-level `embed_fn(texts)` calls that
already pass a list remain unchanged.

---

### CR-02: guard zip truncation with vector count check in bundle functions

**Files modified:** `loaders/shared_transforms.py`
**Commit:** `05af117`
**Applied fix:** Added a length-equality guard after the `embed_fn(texts)` batch call in both
`prepare_talk_bundle` and `prepare_talk_bundle_rich`. If `len(vectors) != len(all_records)`,
logs an `ERROR` and returns early with empty collections for all 4 collection keys. This prevents
the silent data corruption that would occur when `zip` truncates to the shorter iterable and the
subsequent slice redistribution uses pre-computed lengths derived from the original (longer) counts.

**Commit:** `93db821`

### WR-02: close worker loaders immediately after pool exits instead of deferring to atexit

**Files modified:** `benchmark/runner.py`
**Commit:** `f8b8789`
**Applied fix:** Replaced `atexit.register(_tls.loader.close)` in `_init_worker` with an explicit
tracking approach: added module-level `_worker_loaders: list` and `_worker_loaders_lock: threading.Lock`.
`_init_worker` appends each created loader to `_worker_loaders` under the lock. In
`run_upsert_phase`, the list is cleared before the pool starts (so each run starts fresh), and
after the `with ThreadPoolExecutor(...)` block exits, all tracked loaders are closed and the list
is cleared. This ensures connections are released as soon as the pool completes, not deferred to
process exit.

### WR-03: exclude failed query latency from serial and filtered/unfiltered stats

**Files modified:** `benchmark/runner.py`
**Commit:** `e29f3a2`
**Applied fix:** In `run_serial_latency` and `run_filtered_unfiltered._run_group`, changed the
pattern to record elapsed time before the `if ids is None` check and only append to `latencies`
(or `lats`) in the `else` branch. Failed queries still increment the `failed`/`fails` counter
so `QueryMetrics.failed_queries` remains accurate, but their error-path timing no longer contaminates
the p50/p95/p99/mean statistics. This matches the `_timed_query` pattern used elsewhere.
