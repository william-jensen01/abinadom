## Phase Boundary

Reduce benchmark upsert time from 2–7 hours to a feasible range for Phase 23 by:
1. Batching Ollama embedding calls — one `embed_fn(texts: list[str])` call per talk bundle instead of one per record.
2. Parallelizing talk loading across all three DBs with a `ThreadPoolExecutor` controlled by `--workers`.

Files in scope: `loaders/embeddings.py`, `loaders/shared_transforms.py`, `loaders/weaviate_loader.py`, `benchmark/runner.py`, and the three loader test files. Production loader (`extractors/phase6_chromadb_loader.py`) is explicitly out of scope.

<decisions>
## Implementation Decisions

### --workers flag
- **D-01:** Reuse the existing `--workers` flag for both upsert parallelism and query concurrency. Change the default from `10` → `5`. One flag, one knob.
  - Rationale: simpler CLI; `--workers 5` matches the `[1, 5, 10, 20]` scalability curve entry so `run_latency_under_load` finds a valid match without fallback.
- **D-02:** Scalability curve worker levels (`[1, 5, 10, 20]`) stay unchanged — no code change needed there.

### Weaviate insert_many error handling
- **D-03:** After each `col.data.insert_many(objects)` call, if `result.has_errors`: log one `WARNING` per failed object with `class_name` and the object's UUID.
  - Pattern: `logger.warning("Weaviate insert error in %s: %s", class_name, uuid)`
  - Mirrors the existing `col.batch.failed_objects` iteration pattern.
- **D-04:** If `insert_many` raises an exception (not just returns errors): catch, log `WARNING` with `class_name` and the exception, and continue to the next collection. Never crash a talk load — consistent with how current batch errors are handled.

### Thread-local loader lifecycle
- **D-05:** Use `ThreadPoolExecutor(max_workers=args.workers, initializer=_init_worker, initargs=(db_name, args))`. Each thread stores its loader in `threading.local()`.
  - Pattern:
    ```python
    _tls = threading.local()

    def _init_worker(db_name, args):
        _tls.loader = _build_loader(db_name, args)
        atexit.register(_tls.loader.close)
    ```
- **D-06:** Cleanup via `atexit.register(loader.close)` inside the initializer — mirrors the existing `atexit.register(_client._client.close)` pattern in `loaders/embeddings.py` (line 24). No explicit post-pool cleanup loop needed.

### Weaviate schema race (implicit)
- **D-07:** Schema pre-creation is handled naturally — `BenchmarkRunner.__init__` creates `self._loader` (which calls `WeaviateLoader._ensure_schema()`) before the thread pool starts. Worker threads find collections already existing and skip creation. No code change to `_ensure_schema()` needed.

### Claude's Discretion
- Whether `prepare_talk_bundle` and `prepare_talk_bundle_rich` share a single batching helper or each inline the collect-embed-distribute loop
- Exact number of `DataObject` instances per `insert_many` call (one per collection per talk, as before)
- Whether to update `embed_fn` type annotations on all three loader `__init__` methods in addition to `shared_transforms.py`

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `atexit.register(_client._client.close)` pattern (`loaders/embeddings.py` line 24): use same pattern for thread-local loader cleanup inside `_init_worker`
- `threading` module already imported in `benchmark/runner.py` (line 21) and `ThreadPoolExecutor`, `as_completed` already imported (line 23) — no new imports needed for the parallel upsert
- `_build_loader(db_name, args)` factory (`runner.py` line 567): call it in `_init_worker` to create per-thread loaders; switch `embed_fn=embed` → `embed_fn=embed_batch` here

### Established Patterns
- `embed_fn: Callable[[str], list[float]] | None = None` appears in every `prepare_*` function in `shared_transforms.py` — all 8 functions need the type updated to `Callable[[list[str]], list[list[float]]] | None`
- Weaviate `load()` currently builds one `DataObject`-like dict per record and feeds it to `batch_ctx.add_object(properties=..., uuid=..., vector=...)` — the `insert_many` refactor collects these into a `list[wvc.data.DataObject]` per collection and calls `col.data.insert_many(objects)` once per collection
- `col.batch.failed_objects` iteration for Weaviate error logging (lines 243–249) is replaced by `result.errors.items()` iteration from `insert_many` return value

### Integration Points
- `BenchmarkRunner.__init__` creates `self._loader` before any upsert — guarantees Weaviate schema is pre-created before worker threads start (D-07)
- `run_upsert_phase()` today uses `self._loader.load(bundle)` sequentially — after the change, worker threads use `_tls.loader.load(bundle)` while `self._loader` remains reserved for the query phase
- `run_memory_query()` (line 372) and `run_latency_under_load()` (line 404) both use `self._config.workers` — with default now 5, `run_latency_under_load` will correctly find the `[1, 5, 10, 20]` curve entry at 5

</code_context>

## Specific Ideas

- The collect-embed-distribute pattern for `prepare_talk_bundle`: gather all `document` strings into one list, call `embed_fn(texts)` once, zip the result vectors back to their records by index
- `embed_batch` in `embeddings.py` is a thin wrapper: `response = _client.embed(model=model, input=texts); return [list(v) for v in response.embeddings]`
- Weaviate `DataObject` import: `from weaviate.classes.data import DataObject` (or via `wvc.data.DataObject`)
