<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ThreadPoolExecutor workers -> DB connections | Each worker creates its own DB connection; no shared state between threads |
| runner.py -> SQLite content_db | Read-only access from multiple threads; SQLite in WAL mode handles concurrent reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22.2-06 | Denial of Service | ThreadPoolExecutor with N workers | accept | Worker count is user-controlled; default 4 is conservative |
| T-22.2-07 | Tampering | Thread-local loader state | accept | Each thread has isolated loader; no shared state; atexit cleanup prevents leaks |
| T-22.2-08 | Denial of Service | SQLite concurrent reads from workers | accept | content_db and core_db are read-only in upsert path; SQLite handles concurrent reads |
</threat_model>
