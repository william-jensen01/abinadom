# Phase 16.2 Context — FastAPI MCP Protocol Rewrite

**Added:** 2026-04-08  
**Depends on:** Phase 16.1 (in progress)  
**Reason for split:** `BaseHTTPMiddleware` + FastMCP are structurally incompatible. FastMCP uses anyio task groups internally; `call_next()` wraps downstream in a background task with a new async scope, severing the task group context and causing `RuntimeError: Task group is not initialized`. Every significant problem in Phase 16.1 (task group error, `/mcp` path, can't make `initialize` public, can't do per-method auth) traces back to FastMCP.

## What's Kept

- All tool logic: `search()`, `get_talk()`, ChromaDB queries
- `AppContext` dataclass and all startup logic (`_startup`, `_check_ollama`, `_load_collections`)
- `auth/oauth.py` — `JWKSVerifier` (with `kid`-based improvement, see below)
- `auth/middleware.py`, `auth/store.py` — Phase 14 static bearer token fallback
- All helpers: `_build_where_filter`, `_matches_speaker`, `_format_search_result`, `_parse_talk_id`
- `/health`, `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`
- All tests except `test_server.py`

## What's Removed

- `FastMCP`, `@mcp.tool()` decorator, `mcp.streamable_http_app()`
- `BaseHTTPMiddleware` / `JWTAuthMiddleware`
- The `/mcp` path (server now listens at `/`)

## Implementation Spec

### 1. `auth/oauth.py` — kid-based token detection

Replace alg-inspection routing with `kid`-presence check:

```python
def verify_token(self, token: str) -> dict | None:
    try:
        header = jwt.get_unverified_header(token)
    except jwt.PyJWTError:
        return self._validate_via_userinfo(token)

    if header.get("kid"):
        return self._verify_asymmetric(token, header["alg"])
    else:
        return self._validate_via_userinfo(token)
```

Removes: `SYMMETRIC_ALGORITHMS`, `ASYMMETRIC_ALGORITHMS`, dot-counting, alg-based branching.

### 2. `server.py` — FastAPI + manual MCP JSON-RPC

**Endpoints:**
```
GET  /health                                 — no auth
GET  /.well-known/oauth-protected-resource   — no auth (RFC 9728)
GET  /.well-known/oauth-authorization-server — no auth (RFC 8414 proxy)
HEAD /                                       — no auth, MCP-Protocol-Version header
GET  /                                       — no auth, 405 response
POST /                                       — MCP JSON-RPC dispatcher
DELETE /                                     — session cleanup
```

**Auth per MCP method (inside POST handler):**
| Method | Auth required |
|--------|--------------|
| `initialize` | None |
| `notifications/initialized` | Session ID only |
| `tools/list` | Full OAuth token + session |
| `tools/call` | Full OAuth token + session |

**Session management:** In-memory dict. `initialize` generates UUID session ID returned in `MCP-Session-ID` response header.

**Static fallback:** When `AUTH0_DOMAIN` unset, `tools/list`/`tools/call` fall back to `SqliteKeyStore` bearer check. `initialize` stays public.

**Response headers:** Every MCP response includes `MCP-Protocol-Version: 2025-06-18` and `MCP-Session-ID: {id}`.

### 3. `tests/test_server.py` — update for new routing

Remove: `streamable_http_app()`, `mcp.run()` references.  
Keep: `/health` tests (same route), tool tests (same logic, different invocation).

## Reference Implementation

`georgevetticaden/multi-agent-federal-form-automation-system` — working MCP server with Auth0 DCR, Claude Desktop, Cursor. FastAPI + manual MCP protocol. No FastMCP.

## Connection Flow (Post-Rewrite)

```
1. Operator sets MCP URL to https://host/ in Claude Desktop / Cursor
2. Client: HEAD /  →  200 + MCP-Protocol-Version: 2025-06-18
3. Client: POST /  {method: "initialize"}  →  200, no auth
   Server creates session, returns MCP-Session-ID header
4. Client: POST /  {method: "notifications/initialized"}  →  202
5. Client: POST /  {method: "tools/list"}  →  401
   WWW-Authenticate: Bearer resource_metadata="https://host/.well-known/oauth-protected-resource"
6. Client fetches /.well-known/oauth-protected-resource → discovers Auth0
7. Client does DCR → client_id + client_secret (HS256)
8. Client completes authorization_code flow → access token (HS256, no kid)
9. Client: POST /  {method: "tools/list"} + Authorization: Bearer {token}
   Server: no kid → _validate_via_userinfo() → 200 → valid
10. tools/call works the same way.
```
