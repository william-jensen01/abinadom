## What Was Built

### Task 1: FastAPI + kid-based JWT routing

**FastAPI installation:** `fastapi==0.135.3` added to Pipfile, Pipfile.lock regenerated, requirements.txt updated for Docker builds.

**auth/oauth.py changes:**
- `verify_token` rewritten: `ASYMMETRIC_ALGORITHMS` and `SYMMETRIC_ALGORITHMS` class attributes removed
- New routing: JWE (4 dots) → `_validate_via_userinfo`, JWT with `kid` → `_verify_asymmetric`, JWT without `kid` → `_validate_via_userinfo`

- `_verify_symmetric` removed (all symmetric tokens now go to /userinfo)
- `_verify_asymmetric` updated to catch generic `Exception` in addition to `jwt.PyJWTError` (JWKS network failures)

**tests/test_oauth.py:** Rewritten from 12 tests to 14 tests. Tests updated to mock `httpx.Client` for the /userinfo path. Two new tests added: `test_verify_rs256_without_kid_routes_to_userinfo` and `test_verify_hs256_with_kid_routes_to_jwks`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Catch generic Exception in _verify_asymmetric**
- **Found during:** Task 1 — test_verify_hs256_with_kid_routes_to_jwks failing
- **Issue:** `_verify_asymmetric` only caught `jwt.PyJWTError` but JWKS client `get_signing_key_from_jwt` can throw plain `Exception` (network errors, key-not-found). Test mock raised `Exception("key not found")` which propagated uncaught.
- **Fix:** Added `except Exception as exc: logger.warning(...); return None` after the `jwt.PyJWTError` handler
- **Files modified:** auth/oauth.py
- **Commit:** 53b02ee

**2. [Rule 2 - Missing functionality] Add _validate_via_userinfo method**
- **Found during:** Task 1 planning — plan spec referenced `self._validate_via_userinfo()` but method did not exist in oauth.py
- **Issue:** Plan's new `verify_token` calls `_validate_via_userinfo` but the method was not in the existing codebase. The plan says "Keep `_validate_via_userinfo` unchanged" implying it should exist — deviation from plan assumption.
- **Fix:** Implemented `_validate_via_userinfo` using `httpx.Client` to call Auth0's `/userinfo` endpoint with the token as Bearer. Returns userinfo payload on 200, None otherwise.
- **Files modified:** auth/oauth.py
- **Commit:** 53b02ee

**3. [Rule 1 - Bug] JWE routing changed to /userinfo (plan spec)**
- **Found during:** Task 1 planning
- **Issue:** CONTEXT.md spec omits the JWE 4-dot check from new `verify_token`, but plan acceptance criteria explicitly requires `token.count(".") == 4` to be preserved. Plan spec code shows JWE routing to `/userinfo` (not local decrypt). Old behavior was local JWE decrypt via `_decrypt_jwe`.
- **Fix:** JWE tokens now route to `_validate_via_userinfo` (plan spec). `_decrypt_jwe` retained but no longer called from `verify_token`. JWE tests updated to mock httpx instead of testing decrypt path.
- **Files modified:** auth/oauth.py, tests/test_oauth.py
