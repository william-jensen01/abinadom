## What Was Built

### Task 1: server.py FastAPI rewrite

**Removed entirely:**
- `from mcp.server.fastmcp import FastMCP, Context`
- `from starlette.middleware.base import BaseHTTPMiddleware`
- `mcp = FastMCP(...)` instantiation
- `@mcp.tool()` decorators on `search` and `get_talk`
- `class JWTAuthMiddleware(BaseHTTPMiddleware)` middleware class
- Old `def lifespan(server: FastMCP)` with FastMCP signature

**Added:**
- `import uuid` and `from fastapi import FastAPI, Request` / `from fastapi.responses import JSONResponse, Response`
- `MCP_INSTRUCTIONS` module-level constant (extracted from old FastMCP constructor)
- `class _FakeMCPCtx` — bridge so `search`/`get_talk` can still access `ctx.request_context.lifespan_context` without any tool function changes
- `_sessions: dict[str, dict] = {}` — in-memory session dict; sessions created by `initialize` via `uuid.uuid4()`
- `_mcp_response()` — sets `MCP-Protocol-Version: 2025-06-18` and optional `MCP-Session-Id` header
- `_error_response()` — builds JSON-RPC error body
- `_unauthorized_response()` — 401 with `WWW-Authenticate: Bearer ... resource_metadata=...` per RFC 9728
- `_verify_auth()` — checks Authorization header; routes to JWKSVerifier when AUTH0_DOMAIN set, SqliteKeyStore otherwise
- `_key_store` static fallback initialized when AUTH0_DOMAIN unset
- `_handle_initialize()` — public (no auth), returns protocolVersion + capabilities + serverInfo + instructions
- `_handle_tools_list()` — requires auth + session, returns full tool schemas for search and get_talk
- `_handle_tools_call()` — requires auth + session, dispatches to search/get_talk via _FakeMCPCtx, logs via SqliteKeyStore
- `def lifespan(app: FastAPI)` — FastAPI lifespan context manager
- `def build_app() -> FastAPI` — factory with all 7 routes: GET /health, GET /.well-known/*, HEAD /, GET / (405), POST / (dispatcher), DELETE / (session cleanup)

**Preserved verbatim:**
- All helper functions: `_resolve_chromadb_path`, `_check_ollama`, `_load_collections`, `_startup`, `_build_where_filter`, `_matches_speaker`, `_format_search_result`, `_parse_talk_id`
- Tool functions `search` and `get_talk` (ctx parameter changed from `Context` type annotation to plain `ctx=None`)
- `health_check`, `_protected_resource_metadata`, `_auth_server_metadata`

## Threat Surface Scan

All T-16.2-03 through T-16.2-10 mitigations applied as specified in the plan's threat model:
- T-16.2-03 (Spoofing): Session ID generated server-side via `uuid.uuid4()` — client cannot choose their own session ID

No new threat surfaces introduced beyond what was planned.
