### Human Verification Required

#### 1. End-to-End OAuth 2.1 Handshake

**Test:** Start the server (`pipenv run py server.py`) with `AUTH0_DOMAIN`, `AUTH0_AUDIENCE`, and `MCP_BASE_URL` set. Configure Claude Desktop or Cursor to connect at the server URL. Observe the full connection sequence in server logs.

**Expected:**
- HEAD / returns 200 with `MCP-Protocol-Version: 2025-06-18`
- POST / with `initialize` returns 200 with session ID and no auth required
- POST / with `tools/list` (no token) returns 401 with `WWW-Authenticate: Bearer ... resource_metadata=...`
- Client fetches `/.well-known/oauth-protected-resource`, discovers Auth0
- Client completes DCR + authorization_code flow with Auth0, obtains HS256 access token
- POST / with `tools/list` + `Authorization: Bearer <token>` returns 200 with tool schemas
- `tools/call` for `search` and `get_talk` returns real ChromaDB results

**Why human:** Full OAuth 2.1 DCR + authorization_code flow requires a live Auth0 tenant, a running server at a public URL, and an MCP client (Claude Desktop or Cursor) to initiate the handshake. Cannot be replicated in unit tests.

#### 2. Live Tool Execution Through HTTP Dispatcher

**Test:** With the server running and authenticated, call `search` with a query like `"atonement of Jesus Christ"` and `get_talk` with a known `talk_id`.

**Expected:** `search` returns non-empty JSON results from ChromaDB paragraphs collection; `get_talk` returns formatted talk text with speaker, title, conference, and paragraph body.

**Why human:** Unit tests use a mock `AppContext` with empty collections. Live ChromaDB + Ollama embedding is required to verify actual data flows through the dispatcher to tool functions and back.
