  <action>
Create `Dockerfile` in project root with this exact content:

```dockerfile
FROM python:3.12-slim

RUN apt-get update && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Fixed container-internal paths (D-06, D-07) — NOT operator-facing
ENV CHROMADB_PATH=/data/chromadb
ENV AUTH_DB_PATH=/data/auth.db

# Default host/port — overridable via .env / env_file in compose
ENV MCP_HOST=0.0.0.0
ENV MCP_PORT=8000

EXPOSE 8000

CMD ["python", "server.py"]
```

Key decisions implemented:
- `python:3.12-slim` base image (per RESEARCH — onnxruntime lacks 3.14 wheels, Pitfall 4)
- `curl` installed for healthcheck probe (used by compose.yml healthcheck CMD)
- Layer ordering: requirements.txt copied and installed BEFORE source (cache efficiency)
- `CHROMADB_PATH=/data/chromadb` fixed internally (per D-06)
- `AUTH_DB_PATH=/data/auth.db` fixed internally (per D-07)
- `MCP_HOST=0.0.0.0` and `MCP_PORT=8000` as defaults (discretion: set in Dockerfile for container-ready defaults)
- `CMD ["python", "server.py"]` matches the existing entry point at server.py line 450

Create `.dockerignore` in project root to prevent large/sensitive files from entering the build context:

```

```

This excludes: git metadata, planning docs, databases, ChromaDB data directory, test/script files not needed at runtime, and .env files. The image only contains server.py, extractors/, config/, models/, auth/, Pipfile, requirements.txt, and supporting Python modules.
