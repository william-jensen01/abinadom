Rewrite config/ollama.py completely. Remove the import of OllamaEmbeddingFunction from
chromadb.utils.embedding_functions. Implement a plain callable class that replicates the
interface: accepts a list of strings, returns a list of float vectors via requests HTTP POST

production dependency in server.py for the health check).

Public API to preserve exactly (callers must not change):
- resolve_ollama_url() -> str: reads OLLAMA_URL env var, defaults to "http://localhost:11434"
- get_embedding_function(url: str | None = None) -> callable: returns an object/function
  that accepts list[str] and returns list[list[float]]

Implementation details:
- Create a class (e.g. OllamaEmbedder) with a __call__(self, texts: list[str]) -> list[list[float]] method
- The __call__ method posts to {base_url}/api/embeddings with payload {"model": "nomic-embed-text", "prompt": text} for each text in the list, collecting the "embedding" from each response
- The Ollama /api/embeddings endpoint accepts one text per request — iterate over texts and collect embeddings individually. Build a list of float vectors, one per input text, and return it.
- get_embedding_function(url=None) instantiates and returns OllamaEmbedder(base_url=url or resolve_ollama_url(), model="nomic-embed-text")
- Import: os, requests (stdlib + already in Pipfile [packages])
- Do NOT import anything from chromadb in this file

The existing test in test_server.py patches "config.ollama.OllamaEmbeddingFunction" — that
patch will break. Note: test_server.py is being fully rewritten in Plan 24-08, so those
tests are already going away. The three tests (test_ollama_url_env_override,
test_get_embedding_function_url_param, test_get_embedding_function_default_url) in the
existing test_server.py currently patch config.ollama.OllamaEmbeddingFunction. After this
rewrite those tests will break — that is acceptable because Plan 24-08 rewrites test_server.py.
The Ollama API URL and behavior must remain identical: base_url + "/api/embeddings".
