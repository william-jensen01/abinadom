# Phase 21: DB Loaders — Specification

**Created:** 2026-04-21
**Ambiguity score:** 0.19 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

Each of the three vector DBs (ChromaDB, Weaviate, Qdrant) has a dedicated loader in `loaders/` that accepts talk bundles with pre-computed embedding vectors, creates fully typed schemas/collections, and persists records across 4 collections (talks, paragraphs, citations, footnotes) — all using `shared_transforms` from Phase 20.

## Background

Phase 20 delivered the shared infrastructure: `loaders/shared_transforms.py` (flatten_metadata, rich_metadata, prepare_* functions, TalkBundle type), `benchmark/metrics.py` (dataclasses + recall_at_k), `benchmark/queries.py` (8 canonical queries), and `infra/docker-compose.vector-dbs.yml` (ChromaDB on 8000, Weaviate on 8080, Qdrant on 6333).

The production ChromaDB loader (`extractors/phase6_chromadb_loader.py`) handles the pipeline's loading needs but is tightly coupled to pipeline orchestration and generates embeddings at insert time via Ollama. No Weaviate or Qdrant loaders exist. Neither `weaviate-client` nor `qdrant-client` are in the Pipfile.

The current `prepare_talk_bundle()` returns `(doc, metadata, id)` tuples with `flatten_metadata` (ChromaDB-safe scalars). Weaviate and Qdrant support native arrays, so they need `rich_metadata` — but no `prepare_talk_bundle_rich()` variant exists yet.

For fair benchmarking (Phase 22–23), all three DBs must receive identical pre-computed embedding vectors rather than each DB generating its own. The current record tuple shape `(doc, metadata, id)` does not carry vectors.

## Requirements

1. **ChromaDB Benchmark Loader**: A standalone benchmark loader inserts talk bundles into ChromaDB using pre-computed vectors.
   - Current: No benchmark-specific ChromaDB loader exists. The production loader (`extractors/phase6_chromadb_loader.py`) generates embeddings at insert time and is coupled to pipeline orchestration.
   - Target: `loaders/chromadb_loader.py` accepts talk bundles with pre-computed vectors, creates/gets 4 collections (talks, paragraphs, citations, footnotes), and upserts records using `flatten_metadata`. Independent from the production loader — no imports from `extractors/phase6_chromadb_loader.py`.
   - Acceptance: Inserting a sample talk bundle into a test ChromaDB instance succeeds; querying the paragraphs collection by vector returns the expected paragraph record with correct metadata.

2. **Weaviate Loader**: A loader creates typed Weaviate classes and batch-loads talk bundles with pre-computed vectors.
   - Current: No Weaviate loader or client dependency exists. `weaviate-client` is not in Pipfile.
   - Target: `loaders/weaviate_loader.py` creates 4 Weaviate classes with fully typed property schemas (every metadata field explicitly typed), generates deterministic UUIDs from doc IDs, and batch-inserts records using `rich_metadata`. Vectors are passed explicitly (not generated by a Weaviate vectorizer module).
   - Acceptance: Inserting a sample talk bundle into a test Weaviate instance succeeds; a near-vector query on the paragraphs class returns the expected paragraph object with correct properties.

3. **Qdrant Loader**: A loader creates Qdrant collections with payload indexes and batch-loads talk bundles with pre-computed vectors.
   - Current: No Qdrant loader or client dependency exists. `qdrant-client` is not in Pipfile.
   - Target: `loaders/qdrant_loader.py` creates 4 Qdrant collections with explicit payload indexes for all metadata fields, and batch-upserts records as PointStruct objects using `rich_metadata`. Vectors are passed as named vectors or the default vector field.
   - Acceptance: Inserting a sample talk bundle into a test Qdrant instance succeeds; a vector search on the paragraphs collection returns the expected point with correct payload fields.

4. **Rich Metadata Transform**: A `prepare_talk_bundle_rich()` function produces records using `rich_metadata` instead of `flatten_metadata`.
   - Current: `prepare_talk_bundle()` in `shared_transforms.py` only produces flat metadata (ChromaDB-safe scalars). `rich_metadata()` exists but no bundle-level function uses it.
   - Target: `loaders/shared_transforms.py` gains `prepare_talk_bundle_rich()` that mirrors `prepare_talk_bundle()` but calls `rich_metadata` throughout (and `prepare_paragraph_records_rich`, etc. as needed). Returns the same dict structure with `(doc, metadata, id)` tuples using native types.
   - Acceptance: Calling `prepare_talk_bundle_rich()` with a sample talk bundle returns metadata dicts where list fields (e.g., `topics`, `verse_list`) are preserved as Python lists, not joined strings.

5. **Pre-computed Embedding Vector Support**: The record tuple shape extends to carry vectors for all loaders.
   - Current: `prepare_talk_bundle()` returns `(doc, metadata, id)` tuples. No vector field.
   - Target: Both `prepare_talk_bundle()` and `prepare_talk_bundle_rich()` return `(doc, metadata, id, vector)` tuples where `vector` is `list[float] | None`. When `None`, the loader is responsible for embedding (backward compat for non-benchmark use). An embedding helper function accepts document text and returns a vector via the Ollama nomic-embed-text model.
   - Acceptance: `prepare_talk_bundle()` output tuples have 4 elements; when an embedding function is provided, the vector field is a non-empty `list[float]`; when no embedding function is provided, the vector field is `None`.

6. **Python Client Dependencies**: Weaviate and Qdrant client libraries are added to the project.
   - Current: Only `chromadb` is in the Pipfile. No `weaviate-client` or `qdrant-client`.
   - Target: `weaviate-client` and `qdrant-client` are added to Pipfile as dependencies. Versions pinned to match the Docker image versions in `docker-compose.vector-dbs.yml` (Weaviate 1.37.x client, Qdrant 1.17.x client).
   - Acceptance: `pipenv install` succeeds; `import weaviate` and `import qdrant_client` resolve without error.

## Boundaries

**In scope:**
- `loaders/chromadb_loader.py` — benchmark ChromaDB loader (separate from production phase6 loader)
- `loaders/weaviate_loader.py` — Weaviate loader with full typed schemas
- `loaders/qdrant_loader.py` — Qdrant loader with payload indexes
- `prepare_talk_bundle_rich()` and supporting `_rich` variants in `shared_transforms.py`
- Extended record tuple `(doc, metadata, id, vector)` in both flat and rich prepare functions
- Embedding helper function (calls Ollama nomic-embed-text, returns vector)
- `weaviate-client` and `qdrant-client` added to Pipfile
- Tests for each loader (insert + query round-trip against Docker instances)

**Out of scope:**
- Modifying the production ChromaDB loader (`extractors/phase6_chromadb_loader.py`) — it stays as-is for pipeline use
- Benchmark runner CLI (`benchmark/runner.py`) — that is Phase 22
- Full dataset loading (5,838 talks) — that is Phase 23; Phase 21 proves correctness with sample bundles
- Recall@k computation across DBs — that is Phase 22–23
- Collection naming conventions for production — Phase 24 decides production collection names
- Embedding model selection or tuning — uses existing Ollama nomic-embed-text as-is

## Constraints

- All 3 loaders must use `prepare_talk_bundle()` or `prepare_talk_bundle_rich()` from `shared_transforms.py` — no inline transformation logic
- Weaviate vectorizer module must be set to `none` (vectors are pre-computed, not generated by Weaviate)
- Qdrant vector size must match nomic-embed-text output dimension (768)
- Weaviate and Qdrant client library versions must be compatible with the Docker image versions in `docker-compose.vector-dbs.yml` (Weaviate 1.37.1, Qdrant v1.17.1)
- Each loader must support idempotent loading (upsert semantics) — re-loading the same talk must not create duplicates
- `prepare_talk_bundle()` backward compatibility must be preserved — existing tests and phase6 caller must not break

## Acceptance Criteria

- [ ] `loaders/chromadb_loader.py` exists and inserts a sample talk bundle; vector query returns the expected paragraph
- [ ] `loaders/weaviate_loader.py` exists, creates typed classes, and inserts a sample talk bundle; near-vector query returns the expected paragraph
- [ ] `loaders/qdrant_loader.py` exists, creates collections with payload indexes, and inserts a sample talk bundle; vector search returns the expected point
- [ ] `prepare_talk_bundle_rich()` returns metadata with native Python lists (not joined strings)
- [ ] Both `prepare_talk_bundle()` and `prepare_talk_bundle_rich()` return 4-element tuples `(doc, metadata, id, vector)`
- [ ] `pipenv install` succeeds with `weaviate-client` and `qdrant-client` in Pipfile
- [ ] Existing `tests/test_shared_transforms.py` and `tests/test_phase6.py` still pass (backward compat)
- [ ] Each loader's test performs a round-trip: insert sample bundle, query by vector, verify returned record matches
