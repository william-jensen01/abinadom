## Success Criteria Verdict

### SC-1: Claude Desktop OAuth handshake completes against this server

**Verdict: PASS (conditional on human verification)**

The code structurally delivers the complete OAuth discovery chain:

1. `tools/list` without token → `_unauthorized_response()` → 401 + `WWW-Authenticate: Bearer realm="lds-mcp", resource_metadata="https://.../well-known/oauth-protected-resource"`
2. Client fetches `/.well-known/oauth-protected-resource` → `{"resource": "...", "authorization_servers": ["https://{AUTH0_DOMAIN}"], "bearer_methods_supported": ["header"]}`
3. Client fetches `/.well-known/oauth-authorization-server` → proxied Auth0 OIDC metadata
4. User authenticates → JWT issued → subsequent requests with `Authorization: Bearer <jwt>` validated by `JWKSVerifier`

The user-confirmed end-to-end test (documented in the planning context) verifies this chain works live. Automated verification of the Claude Desktop UI interaction is not possible.

### SC-2: Server implements RFC 9728 and proxies RFC 8414

**Verdict: PASS**

- `/.well-known/oauth-protected-resource` — registered, returns required JSON (resource, authorization_servers, bearer_methods_supported)
- `/.well-known/oauth-protected-resource/mcp` — same handler, both paths registered
- `/.well-known/oauth-authorization-server` — proxies `https://{AUTH0_DOMAIN}/.well-known/openid-configuration` via async httpx call

### SC-3: Static bearer token auth removed; Auth0 JWT is sole auth path when AUTH0_DOMAIN is set

**Verdict: PASS**

The conditional logic is clean and mutually exclusive:
- `AUTH0_DOMAIN` set → `_jwt_verifier` instantiated, `_key_store` is None → `_verify_auth()` uses only JWKSVerifier
- `AUTH0_DOMAIN` unset → `_jwt_verifier` is None, `_key_store` instantiated → `_verify_auth()` uses only SqliteKeyStore

No code path accepts a static bearer token when `_jwt_verifier` is active. The mcpauth library is absent from requirements.txt and Pipfile.
