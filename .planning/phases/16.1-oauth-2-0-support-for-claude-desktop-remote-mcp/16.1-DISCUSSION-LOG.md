## Clarifying Question: Purpose of OAuth

**User's question:** Is OAuth here to access external services (like Notion), or to authenticate users to this MCP server?

**Answer provided:** Phase 16.1 is the latter — authenticating users so Claude Desktop can connect without manually pasting a bearer token. The server acts as a Resource Server; OAuth replaces the manual bearer token copy-paste with a browser-based login flow. Accessing external services (acting as an OAuth client to Notion, etc.) is a completely different role and not in scope.

| Auth0 + mcp-auth | Auth0 as AS, mcp-auth for Resource Server validation | ✓ |
| GitHub OAuth + mcp-auth | GitHub as AS, mcp-auth for validation | |
| Clerk | Frontend-focused auth platform | |

**User's choice:** Auth0 + mcp-auth
**Notes:** User asked about Clerk and Auth0 as simplification options, then specifically about mcp-auth. After research confirmed mcp-auth is a Resource Server library (not a full AS), user confirmed Auth0 + mcp-auth combination. Key rationale: "offload the auth handling to Auth0 and use mcp-auth to talk with it — everything updates and I don't need to regularly maintain."

## Identity Providers

**User's question:** What providers does Auth0 offer? What does the login look like for users?

**Login UX explained:** Browser opens to Auth0 Universal Login page → user clicks "Continue with Google/GitHub" → browser closes → Claude Desktop has a token. One-time friction, then invisible.

**Selected providers:** Google + GitHub (covers the developer-focused user base for a shared LDS scripture tool)
