# Plan 05 Summary — Replace mcpauth with Algorithm-Agnostic JWT Verifier

## What Was Built

Replaced the `mcpauth` PyPI dependency with a self-contained `JWKSVerifier` class built
directly on PyJWT. Added RFC 9728 protected resource metadata endpoints and
WWW-Authenticate headers that complete the OAuth discovery chain for Claude Desktop.

## Tasks Completed

### Task 1: Remove mcpauth, rewrite auth/oauth.py ✓
- Removed `mcpauth==0.1.1` from `requirements.txt` and `Pipfile`, uninstalled from virtualenv
- Rewrote `auth/oauth.py` entirely: `JWKSVerifier` class with header-inspection +
  algorithm-agnostic verification (asymmetric JWKS path + symmetric HMAC path)
- Rejects `alg=none` and all unknown algorithms explicitly (T-16.1-01)
- `PyJWKClient` provides JWKS caching with 300s TTL and auto-refresh on unknown kid
- Rewrote `tests/test_oauth.py`: 9 tests covering RS256, ES256, HS256, none rejection,
  unknown alg rejection, expired, wrong audience, wrong issuer, no-secret HMAC rejection
- **All 9 tests pass**

### Task 2: Rewrite server.py — JWT middleware, RFC 9728, WWW-Authenticate ✓
- Replaced `build_mcp_auth` import with `JWKSVerifier`
- Added `JWTAuthMiddleware(BaseHTTPMiddleware)` — enforces JWT on all MCP routes
- Added `_protected_resource_metadata()` at:
  - `/.well-known/oauth-protected-resource`
  - `/.well-known/oauth-protected-resource/mcp`
- 401 responses include `WWW-Authenticate: Bearer resource_metadata="...", error="invalid_token"`
- Moved `/.well-known/oauth-authorization-server` to canonical path (removed `-proxy` suffix)
- Static bearer token fallback (Phase 14) preserved when `AUTH0_DOMAIN` is unset
- Updated CLAUDE.md `auth/oauth.py` description
- **80/80 tests pass** (test_oauth.py + test_server.py + test_auth.py)

## OAuth Discovery Chain (Complete)

```
Claude Desktop
  → POST /mcp (no token)
  ← 401 WWW-Authenticate: Bearer resource_metadata="<url>/.well-known/oauth-protected-resource"
  → GET /.well-known/oauth-protected-resource
  ← {"resource": "...", "authorization_servers": ["https://<domain>"]}
  → GET https://<domain>/.well-known/openid-configuration
  ← Auth0 OIDC metadata (or proxied via /.well-known/oauth-authorization-server)
  → OAuth flow → JWT token
  → POST /mcp Authorization: Bearer <jwt>
  ← 200 (JWKSVerifier validates RS256/ES256/etc via JWKS)
```
