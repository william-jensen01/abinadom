<objective>
Fix Bug 2: WeaviateLoader.query() returns UUID strings instead of doc_id strings.

Purpose: query() currently returns obj.properties.get("id", str(obj.uuid)). The properties dict
has no field named "id", so it falls back to str(obj.uuid) — a UUID5 derived from the doc_id
string. ChromaDB baseline IDs are "para_1234" style strings. UUID != doc_id → zero set
intersection → recall@k = 0.0 even if Bug 1 is fixed.

Root cause is that no doc_id_str property was ever stored in Weaviate objects. The fix adds
doc_id_str to all 4 class schemas and stores it at load time, then reads it back in query().

Output: loaders/weaviate_loader.py with:
  - doc_id_str TEXT property appended to all 4 _*_properties() methods
  - load() injecting doc_id_str into the properties dict for every record
  - query() returning doc_id_str instead of the "id" fallback
</objective>
