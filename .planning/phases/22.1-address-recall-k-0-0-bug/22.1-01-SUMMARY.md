# Phase 22.1 Plan 01: Fix ChromaDBLoader.query() Collection Name Resolution Summary

**One-liner:** Resolved phantom-empty-collection bug in `ChromaDBLoader.query()` by resolving short-key aliases through `CHROMADB_COLLECTION_NAMES` before calling `get_or_create_collection`, matching the resolution already done in `load()`.

## What Was Done

`ChromaDBLoader.query()` was calling `get_or_create_collection(name=collection)` with the raw argument — for example, `"paragraphs"`. ChromaDB's `get_or_create_collection` created a brand-new empty collection called `"paragraphs"` instead of connecting to the existing `"conference_talk_paragraphs"` collection that `load()` had populated.

The `_collect_chroma_baseline()` caller in `runner.py` then received an empty ID list and skipped all queries, leaving `k10_scores = []` and computing `recall@k = 0.0`.

The fix mirrors the resolution already present in `load()`:

```python
# Before (BUG):
col = self._client.get_or_create_collection(name=collection)

# After (FIXED):
coll_name = CHROMADB_COLLECTION_NAMES.get(collection, collection)
col = self._client.get_or_create_collection(name=coll_name)
```

The `.get(collection, collection)` fallback ensures that fully-qualified names like `"conference_talk_paragraphs"` still pass through unchanged, so callers using either form work correctly.
