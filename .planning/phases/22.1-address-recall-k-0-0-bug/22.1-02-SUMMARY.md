# Plan 22.1-02: WeaviateLoader doc_id_str fix Summary

**Added `doc_id_str` TEXT property to all 4 Weaviate class schemas, stored it in `load()`, and fixed `query()` to return doc_id strings instead of UUID fallbacks — eliminating the UUID/doc_id mismatch that caused recall@k = 0.0**

## Performance

- **Duration:** ~6 min
- **Completed:** 2026-04-25
- **Tasks:** 2
- **Files modified:** 1

## Accomplishments
- All 4 Weaviate class schemas (`_talk_properties`, `_paragraph_properties`, `_citation_properties`, `_footnote_properties`) now declare `Property(name="doc_id_str", data_type=DataType.TEXT)` as their last property
- `load()` now stores `{**meta, "doc_id_str": doc_id}` for every batch-upserted object, so the property is populated on all new collections after volume reset
- `query()` returns `obj.properties.get("doc_id_str", str(obj.uuid))` instead of `obj.properties.get("id", str(obj.uuid))` — the `"id"` key never existed in properties, so the old code always fell back to UUID strings that don't match ChromaDB's "para_1234" baseline IDs
