Create `infra/SETUP.md` — a step-by-step operator walkthrough covering the full journey from zero to a working HTTPS endpoint. The document must include ALL of the following sections in order:

**Title and overview:**
- "# Infra Stack Setup: Caddy + Cloudflare Tunnel"
- Brief explanation: this sets up a shared reverse-proxy stack that gives any service on the server a public HTTPS URL without exposing the host IP.

**Prerequisites section:**
- Docker Engine and Docker Compose v2 installed on the server
- A payment method for domain registration (Cloudflare Registrar charges at-cost, typically $10-15/year for .com)

**Step 1: Create a Cloudflare Account**
- Go to https://dash.cloudflare.com/sign-up
- Create account with email + password
- Verify email

**Step 2: Register a Domain**
- In Cloudflare dashboard, go to Domain Registration > Register Domains
- Search for and register a domain (recommend Cloudflare Registrar for at-cost pricing and integrated DNS)
- Wait for registration to complete (usually instant for new registrations)
- Note: if operator already has a domain elsewhere, they can transfer it to Cloudflare or add the domain to Cloudflare and update nameservers

**Step 3: Create a Named Tunnel**
- Go to Cloudflare Zero Trust dashboard (https://one.dash.cloudflare.com/)
- Navigate to Networks > Tunnels
- Click "Create a tunnel"
- Select connector type: Cloudflared
- Give the tunnel a name (e.g. `home-server`)
- Skip the "Install and run a connector" step (we run it in Docker, not on the host)
- Go to the tunnel's configuration page
- Copy the tunnel token (this is the `TUNNEL_TOKEN` value)

**Step 4: Configure Public Hostname in Cloudflare Dashboard**
- In the tunnel's configuration, go to the "Public Hostnames" tab
- Add a public hostname:
  - Subdomain: `mcp`
  - Domain: select your registered domain (e.g. `example.com`)
  - Service type: `HTTP` (NOT HTTPS — Caddy receives plain HTTP from cloudflared internally)
  - Service URL: `caddy:80`
- Save
- IMPORTANT: The service type MUST be HTTP and the URL MUST be `caddy:80`. If you set HTTPS, cloudflared will try a TLS handshake with Caddy, which is not configured for TLS in this deployment. Cloudflare handles external TLS at the edge.

**Step 5: Copy infra/ to Server and Configure**
```bash
# On the server, copy the infra directory from this repo
cp -r /path/to/repo/infra ~/infra

# Create .env from the example
cd ~/infra
cp .env.example .env

# Edit .env and fill in:
# TUNNEL_TOKEN=eyJ... (the token from Step 3)
# DOMAIN=example.com (your root domain, NOT mcp.example.com)
nano .env
```

**Step 6: Start the Infra Stack**
```bash
cd ~/infra
docker compose up -d
```
- Verify both containers are running: `docker compose ps`
- Expected: `caddy` and `cloudflared` both show status "Up"
- Check cloudflared logs for tunnel connection: `docker compose logs cloudflared`
- Expected: logs show "Connection ... registered" (tunnel connected to Cloudflare edge)

**Step 7: Start (or Restart) the MCP Stack**
```bash
cd /path/to/mcp-project
docker compose up -d
```
- The MCP stack's docker-compose.yml already references the `proxy` external network (configured in Plan 01)
- IMPORTANT: The infra stack (Step 6) must be running first. If the proxy network doesn't exist, this step will fail with "network proxy declared as external, but could not be found"

**Step 8: Verify End-to-End**
```bash
# From any machine with internet access:
curl -f https://mcp.yourdomain.com/health
```
- Expected: HTTP 200 with JSON body `{"status": "healthy", ...}`
- If this works, the full chain is operational: Internet -> Cloudflare edge (TLS) -> cloudflared -> Caddy -> mcp-server

**Troubleshooting section** with these specific issues:
1. "network proxy declared as external, but could not be found" -> Start the infra stack first (`docker compose up -d` in ~/infra/)
2. curl returns 502 or connection refused -> Check that mcp-server is running and on the proxy network: `docker network inspect proxy` should list both `caddy` and `mcp-server`
3. curl hangs or DNS error -> Verify the DNS CNAME: `dig mcp.yourdomain.com` should return a CNAME to your tunnel UUID
4. cloudflared logs show TLS errors -> Public hostname service type must be HTTP (not HTTPS) with URL `caddy:80`
5. Caddy logs show "environment variable not found" -> Ensure DOMAIN is set in ~/infra/.env

**Adding More Services section** (brief, 5-6 lines):
- To expose another service (e.g. Jellyfin), add it to the proxy network in its own Compose stack
- Add a site block to Caddyfile: `jellyfin.{$DOMAIN} { reverse_proxy jellyfin:8096 }`
- Reload Caddy: `docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile`
- Add a new public hostname in the Cloudflare dashboard pointing to `caddy:80`

**Restarting section:**
- The infra stack should be always-on (`restart: unless-stopped`)
- After a server reboot: `cd ~/infra && docker compose up -d` then `cd /path/to/mcp && docker compose up -d`
- The tunnel token persists in .env — the same public URL is restored automatically (no reconfiguration needed)
